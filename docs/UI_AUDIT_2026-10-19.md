# UI audit — 2026-10-19

# Product & UX ideas (the higher-value list)

The sections below this one are mostly bug/polish checks. This section is about what is missing, what doesn't make sense, and what should be standardized. Grounded in the code as of `main` after PR #27.

## Structure that doesn't quite make sense
- **Three search boxes, three behaviours.** Header search (`AppShell.tsx:419`), Discover's "Starting title" (`App.tsx:852`), and Browse's own search (`BrowsePage.tsx:717`). Discover's box is really "pick a seed title", which is what header search + "Find similar" on the novel page already does. Make header search the one entry point; Discover becomes the results/refine view for a seed.
- **Discover and Browse both own filter UIs.** Discover's "Refine matches" (Show / Leave out / Language / Rating / Results) and Browse's facets are the same idea built twice. One shared filter component + shared URL params would remove a lot of code and make filters feel the same.
- **Profile is a kitchen sink.** One page holds recommendation feedback, taste profile, library, created lists, import, plus a collapsed "Appearance and title settings" that duplicates the Settings page. Split into Library (the shelf, filterable by status) / Taste (what we learned) / Import & data. Remove the duplicated appearance block and link to Settings.
- **Sidebar "Project" links** (GitHub, Report issue, Data repo) take three rows of primary nav. Move to a footer or a Settings "About" section.
- **Format toggles (Novels / Manga / Anime) live in the sidebar** but silently filter every page. When any is off, show a small "Novels only" chip on the page header so results aren't mysteriously short.

## Missing things
- **No page for curated lists.** For You shelves come from curated lists and the novel page shows which lists a title is on, but there is no route to open a list, see all its titles, or follow it. A `?view=list&id=` page would make those shelves and list badges clickable.
- **No first-run path.** A new visitor sees For You with a one-line "Import your library on your profile" hint. A 30-second "pick 5 titles you loved" onboarding (search + tap) would give everyone real recommendations without needing an import.
- **No way to review or undo feedback from the card.** Love / Not for me exist everywhere but you can only manage them deep in Profile. Show an undo toast, and a "Not for me" list you can clear.
- **No "compare" or "why this over that"** — the relationship data exists (shared tags, signals); a compare view of two titles would use it.
- **Mobile has no bottom navigation.** On a phone, For You / Discover / Browse / Library are behind a hamburger. A 4-tab bottom bar is the standard pattern and gets rid of the hamburger drawer for the main flows.
- **Hover card has no touch equivalent.** Phone users never see the synopsis/shared tags the hover card shows on desktop. A tap-to-peek bottom sheet would fix that.

## Repetition to standardize
- **Six different title cards:** For You card, Discover result card (430px, very heavy), Browse card, Related-titles card, search result row, and the hover card. Pick one `NovelCard` with variants (compact cover / list row / detailed) and share rating chip, status badge, badge row, and action buttons. This is the biggest consistency win and also gets rid of the rating-format and amber-color drift.
- **Rating shown in three styles** (amber badge with icon, `★ 4` text, For You overlay star). One `RatingChip`.
- **Stats + "standing" on the novel page** show rating / votes / readers twice (numbers, then percentile). Merge into one block per metric.
- **Native selects and `confirm()` dialogs** next to the styled `Select`/dialogs: finish the migration.
- **Two ways to set reading status** on the novel page (library dropdown and Love/Read buttons) plus a rating; consider one "Your take" control.

## Quick wins
- Sidebar collapse button alignment when collapsed (done on branch `ui/sidebar-polish`).
- Settings: add "For You" as a home option.
- Per-route page titles.

# Bug / polish checks (original audit)


Desktop (1280×800) and mobile (iPhone 12 Pro, 390×844), dark and light theme, against the dev server on `main` after PR #27.

**Method.** Each view was loaded in the preview browser and checked with scripts for horizontal overflow, tap-target size, text under 10.5px, computed text contrast (WCAG AA, 4.5:1 / 3:1 large), unlabeled controls, broken images, plus screenshots and code reading. Values below are measured, not eyeballed.

**Coverage and gaps — read before trusting the list**
- Covered: For You, Discover (landing + results), Browse (structure/audit only), Novel page, Profile (empty state only), Settings.
- **Not covered:** Scraper dashboard (hidden in static deployments), Profile with an imported library (analytics/charts), the library status dropdown on a real phone, tablet widths (600–1000px), keyboard-only navigation, screen readers.
- Browse screenshots timed out in the preview tab, so Browse's visual layout was not reviewed; only scripted checks ran there.
- The audit ran against the stale July 26 local snapshot (30.7k titles, ~19% synopses). Anything data-dependent (empty synopsis text, "not tracked" chapters) is exaggerated locally vs. the live site.
- I tried to measure Browse frame rate; the hidden preview tab throttles animation frames, so that result is **discarded** and no performance claim is made.

Severity: **P1** broken/inaccessible, **P2** visible polish or inconsistency, **P3** nice to have.

## P1 — fix first

### 1. Discover scrolls sideways on mobile (page 442px wide in a 390px viewport)
Hidden tooltips (`.ui-tooltip-content`, `index.css:672`) stay laid out with `visibility:hidden` and extend past the viewport edge (right edge up to 442px). Measured: `document.documentElement.scrollWidth = 442`.
Fix: take hidden tooltips out of flow (`display:none` until shown, or clamp with `max-width`/`overflow-x:clip` on the shell), and check every view that uses `Tooltip` on mobile.

### 2. Novel page scrolls sideways on desktop (+16px)
`.novel-hero:before` (`novel-page.css:65`) is a blurred backdrop with `inset:-2rem -3rem -1rem`, so it extends 48px past the hero. Pre-existing, not from the recent hero regroup. Measured: hero `scrollWidth 1014` vs `clientWidth 966`; page 1296 vs 1280.
Fix: `overflow:clip` on `.novel-hero` (or on `.novel-page`), or reduce the negative inset.

### 3. Light theme: source/format badges are nearly unreadable
`.source-badge.*` / `.format-badge.*` (`index.css:614-619`) use bright dark-theme colors (`#4ade80`, `#38bdf8`, `#93c5fd`, …) on pale tinted backgrounds with no light-theme override. Measured contrast in light theme: NovelUpdates **1.53:1**, Novel **1.58:1**, AniList **1.98:1**, Anime **2.37:1**. These appear on Browse (24 per page), Discover, and the novel page.
Fix: add `[data-theme=light]` (or the existing light-theme selector) variants with darker text, e.g. `#15803d`, `#0369a1`, `#1d4ed8`, `#7e22ce`.

### 4. For You match pill fails contrast (introduced in PR #27)
The `100%` pill on the cover (`.fy-stats .fy-match`, `for-you.css`) is white on `--accent` over the gradient. Measured as low as **2.31:1** (72 instances on the page). Same underlying issue: `.ds-button-primary` white-on-`--accent` is **2.93:1** (Similar buttons, Feeling lucky).
Fix: use a darker accent for filled controls (e.g. `--accent-strong` ~`#6d54d4`), or dark text on the light accent.

### 5. No page titles
`document.title` is never set; every view (For You, Discover, Browse, Novel, Profile, Settings) is "Novel Compass — Relationship-first discovery" (`index.html:7`, no `document.title` in `src`). Hurts tabs, history, bookmarks, screen-reader orientation, and sharing.
Fix: set `document.title` per route; on the novel page use the title (`"The Novel's Extra — Novel Compass"`).

### 6. Settings has no "For You" home option
Settings offers only Discover home / Browse home (`SettingsPage.tsx:41`, `preferences.ts:19,61`), but PR #25 made For You the default home. `loadNavigationPreferences` coerces anything else to `discover`, so a user can't choose For You and the default no longer matches the options shown.
Fix: add `foryou` to `HomeView`, the settings list, and `defaultHomeUrl()`.

## P2 — polish and consistency

### Discover
- **Cards overflow their own width by ~3px** (`.card-main`, `.card-summary`, `h3.novel-title`, `.card-external-link` all +3px). Titles and badge rows get clipped at the right edge ("Warlock of the Magus World", "Chinese" badge cut off). Seen on desktop; the seed header's external-link icon also sits past the card edge on mobile.
- **Rating formatting inconsistent:** `4` vs `3.9` (`★ 4` on one card, `★ 3.9` on the next). Use `toFixed(1)` everywhere ratings render (Discover cards, search result rows `App.tsx:903` prints `novel.rating || '—'` raw).
- **Cards are tall (430px) and repeat themselves:** "Why it matches" and "Shared tropes" both list the same tags. Consider showing one, or collapsing tropes behind a count.
- **Icon-only action buttons** (reading status / love / not for me) have `aria-label`s and tooltips, which is good, but the tooltips are what cause issue P1-1; hide them on touch.
- **"Data source" row on the hero** shows a dropdown and the text "Forced by this deployment" in a static build — a control that can't be used. Hide it when forced, keep the badge only. On mobile the label wraps to two lines ("Data / source").
- **Disabled-looking filter chips** ("For You", "Cross-format") look greyed out with no explanation of why (no profile / not applicable). Add a hint or hide.

### For You
- **Mobile intro is a 5-line paragraph** plus two full-width buttons before any content; the first row of covers is below the fold on a phone. Shorten the copy / collapse it, put the two buttons on one line.
- **"See all"** floats left under the row subtitle on mobile and the arrow nav is gone; align it right of the heading.
- Cover overlay text is 10.2px; fine on dark covers, hard on very light covers (e.g. white/pastel art) because only a bottom gradient helps — consider a slightly taller gradient.
- Hover card is disabled on touch devices (`matchMedia('(hover: hover)')` in `CoverPreview.tsx`), so phone users never see synopsis/shared tags. Consider tap-to-open or a bottom sheet.

### Novel page
- **Empty stat** "— / CHAPTERS / not tracked" takes a whole column for many titles; hide stats with no data.
- **Same-looking amber, three hex values:** `--chart-3` `#d89113`, personal-rating stars `#e3ad42` (`novel-page.css`), warning text `#ffd08a` (`index.css:432`). Pick one token for "rating amber".
- The `Rating / Votes / Readers` standing cards and the stats row both show rating/votes/readers; consider merging into one block (stat + percentile) rather than two rows.
- Long author list links can be very wide (Browse showed a 925px-wide single link, "Mike McFarland, Tets…"); needs wrapping/truncation.
- The "Your rating" stars, "Love/Read/Not for me" and library status all store locally but are three separate controls; consider one "Your take" group.

### Settings / Profile
- Settings layout is clean on mobile (theme and home cards stack well); the only issue found is P1-6.
- Empty Profile: the primary CTA "Import my library" is a small 29px pill, while the empty state below says "Use 'Import my library' above" — put the button inside the empty state card.
- Profile with real data was not audited (charts, import preview).

### Shared / system
- **Native `<select>`s remain in 7 places** while the app has a styled `Select` (`ui.tsx`): `App.tsx:831` (data source), `BrowsePage.tsx:1223`, `ScraperDashboard.tsx:151`, `profile/ProfileImportDialog.tsx:239`, `profile/ProfilePanel.tsx:207`, `profile/ProfilePage.tsx:343,347`. Visible on Discover as the "Recommendation data" select.
- **Native `confirm()` dialogs** for destructive actions in 5 places (`AppShell.tsx:545`, `ScraperDashboard.tsx:315`, `ProfileImportDialog.tsx:51,172`, `ProfilePanel.tsx:149`). Replace with the app's dialog for consistent styling and mobile behavior.
- **`Select` drops `aria-label`** (`ui.tsx:60` doesn't destructure it), so every `Select` trigger lacks a programmatic name beyond its visible text.
- **Rating chip is built by hand in three places** (Browse badge `tone="amber"`, search row `★` text, For You overlay). A small shared `<RatingChip>` would keep format, color, and rounding in sync.
- Mobile tap targets: header icon buttons 36×36, `ds-button` rows 36px, segmented pills 31px, chips ~29px, footer links 30px high. These pass WCAG 2.2 (24px minimum) but are below the 44px platform guidance; the novel page's feedback buttons are already 44px, so the pattern exists.
- Text smaller than 10.5px is used heavily: 93–175 text nodes per page (e.g. `.sidebar-group-label` 9.76px, badges 9.6px, small labels 8.96–9.9px). Combined with muted colors this is the main readability issue on mobile.
- Muted-text contrast: `small`/label text on dark surfaces measures 3.7–4.4:1 in several places ("Relationship-first discovery" 3.74, "Why it matches" 3.96, "Shared tropes" 3.96, "Private to this browser" 3.96, form labels 3.88). `--dim` (`#747482`) is the likely culprit; lift it ~10%.

## Suggested PR split

1. **Overflow + a11y quick wins:** tooltip overflow (P1-1), hero backdrop overflow (P1-2), `document.title` per route (P1-5), `Select` aria-label.
2. **Color/contrast:** light-theme badges (P1-3), accent button + match pill (P1-4), `--dim` lift, one amber token.
3. **Settings:** For You home option (P1-6).
4. **Discover cards:** fix 3px overflow, rating format, drop duplicate tropes, hide forced data-source control.
5. **Shared components:** `RatingChip`, migrate native selects + `confirm()` to shared components.
6. **Mobile polish:** For You intro, See-all alignment, profile empty-state CTA, tap-to-open hover card on touch.

## Re-run the checks

The scripts used are ad-hoc (not committed). To make this repeatable, a Playwright smoke test that loads each `?view=…` at 390px and 1280px and asserts `scrollWidth <= innerWidth` would catch P1-1 and P1-2 automatically; `axe-core` would cover contrast and labels.
